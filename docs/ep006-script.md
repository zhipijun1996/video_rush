# 我只想生成肉鸽地图，怎么开始数学建模了？

AI配音；第一人称按用户自述与开发记录整理，未冒称逐字签收。

我本来只想给游戏做个关卡编辑器。结果现在，我开始搞数学建模了。

我在用AI做肉鸽游戏失序之钟。地图想随机生成，但先得有个地方，让我看懂它到底生成了什么。

所以先做了这个编辑器。把地形、机关、预期动作放在一起，小模块哪里不对，就能具体指出来。

我也可以自己画玩法、补路线、写要求。后面拿它审核小模块、提出新方案，都方便一些。

不过这里画出来的只是草图。看着能跳过去，还得放进真实游戏里验证。

编辑器有了，我想再往前走一步：能不能批量做出有意思的模块，再拼成大地图？

于是让AI查论文、看开源实现。动作语法、图生成、约束求解、多样性搜索，都翻了一圈。

说是让AI生成，其实是让它写生成器，再让程序批量跑。原型、对照、验证，也都跟着做。

但算法能帮我找满足条件的结果，那些条件到底该是什么，还是绕不过去。

先看最早这几版。分支和回环都有，换个种子，图也确实不一样。

结果仔细一看，主干还是那条横向快车道。外面怎么绕，最快的路基本没动。

检查大多通过了，可我想要的是多路线探索。光看那些分数，还发现不了主干根本没变。

后来又改成区域网络，尝试不同入口、地标、奖励和回程。总算开始动骨架了。

再把真实模块接进去，麻烦又来了。图上连一条线，游戏里却得有地方落脚。

从哪个口进、往哪边出、出去时还有多少资源，不能只看两块地形有没有对齐。

中间也确实做出了能跑的小样。反冲、机关、拿奖励再回来，不是完全没进展。

但能跑通以后，再看整张图：路线是不是重复？奖励值不值得绕？跟我想要的还是差一截。

这轮又把模块的形状、端口、动作空间放进搜索。地图看着变了，底下却仍然受同一套骨架限制。

再后来，一版已经能走的地图，因为还是反复串联分叉，又被退回去重做。

版本倒是出了不少。但一轮轮看下来，离我想要的地图，还是差很远。

最近预先定好的三个新种子，三个都在空间求解这一步失败，连实机验证都还没进去。

改一版，看一眼，再改一版。说实话，看到这里，真有点绝望了。

所以现在我决定换个做法。先不指望AI自己找出一套好玩的设计方法，我自己来提炼规则。

比如一段反冲挑战：这一枪要改变什么？该在哪儿落下？操作失误了，还有没有挽回的路？

再看两段怎么接。前一段出去时的速度和资源，够不够开始下一段？不能每接一段，就假装重新来过。

大地图也一样。两条主路得有不同选择，奖励支路得有额外挑战，回程要能接回熟悉的地方。

这些不能只写在名字里。得变成具体要求，落实到模块、位置、机关和资源上，再去验证。

最新也做出了一张能运行的小样，有两条主路，也有不同的奖励返回方式。

但它还只是小样。完整区域、换种子以后能不能稳定产出，还有重复台阶和挑战分布，都没解决。

没想到，最后最费劲的，是把我觉得应该怎么玩的东西，拆成可以描述、可以检查的规则。

这不等于写几个指标，就能算出好玩。规则对不对，生成出来还得看、还得试，还得继续改。

总之，还没成功，正在努力。现在我在人工提炼、建模模块和地图规则，再让AI帮我实现和迭代。

下一期再看看，这样能不能有点改善。大家如果做过关卡生成，欢迎给萌新支点招。
