# 《拍拍波》第一人称故事重制

旧 ep008 已被用户否定，不能视作获准使用的叙事风格。新版本先交付动态粗剪供迭代，不自动投稿。

全片跟着同一个主角：中年工作与带娃的疲惫、老友酒局、拍拍波童年决战、回到手机小游戏。游戏画面承担故事里的动作；其余场景是统一火柴人动画。原片短引用对应游戏王翻卡、波动拳、AT 力场、宇智波反弹、奥特曼光线和承太郎。成年职业、家庭与具体童年决斗属于用户指定的剧情演绎，不当作者履历。

本地使用现有一次性运行副本：

```bash
python -m tools.prepare_wave_story --source build/sources/wave-game --project build/recordings/wave-f0bc22879860/project
python -m tools.capture_wave_story --source build/sources/wave-game --project build/recordings/wave-f0bc22879860/project
python -m tools.make_wave_story
```

新机器可先 `python -m tools.prepare_wave_story` 建立 `build/source` 与 `build/story-runtime`，在后者运行 `npx playwright install --with-deps chromium ffmpeg`，将实际浏览器路径设置为 `VR_CHROMIUM_PATH` 后录制。云端工作流自动执行这些步骤并保留 Artifact 14 天，不依赖手工剪辑。原片通过匿名公开播放获取，按 SHA 固定；访问失败或字节改变会报错，不绕过权限或静默换片。

输出 `build/episodes/ep008-r2-roughcut/`：`roughcut.mp4`、`cover.png`、`bilibili.md`、`script.md`、`storyboard.json`、`subtitles.ass`、`sources.json`、`report.json`、`frame-checks.json`、录音回执与实机轨迹。媒体不进 Git。该剧情需要无旁白的喊招/命中镜头，所以使用独立且明确的粗剪入口，没有往旧版“每镜必须口播”的流程里塞假配音。

实机录制复用源仓库 localhost 钩子和真实 DOM 选招，不修改游戏规则或渲染器。11 组合法起始资源/敌方固定选招演示，逐组验证动作、伤害及胜负；不冒称自然通关。主角用小波被对手魔法筒反杀，和旧演示中“玩家自己用魔法筒”区分。游戏目前是单机对 AI，结尾老友轮流挑战，不宣称真人联机。初始源码逐文件验证 Git blob，配音和媒体按输入及输出哈希缓存；空口播镜头是明确的剪辑留白。

技术验收分开检查整片可解码、1080p/30fps/H.264/AAC、真实 TTS 信号、11 段真实游戏录音信号、字幕边界，以及最终各镜头正文与预期片段是否匹配。已经实际发现并修复两类问题：FFmpeg 不接受部分时长参数的 `.7` 写法；不同来源色彩元数据导致最终混音/字幕图重建并丢掉短镜头。固定同尺寸输入的滤镜图、强制 30fps，并用正文像素对照拒绝“能解码但镜头不对”的文件。画面对照允许最多两帧采样差异，仅检查镜头存在，不代替口型、台词或听感审核。

动漫候选主要为 360/480p，部分已有法语字幕、平台署名或剪辑水印，均保留；不能称为无水印母版或已获授权。游戏自身作品录音和短引用的再发布授权未确认，来源记录如实保留。原创配乐与玻璃杯/铃声音效另记来源，不冒充游戏原声。笑点、对白自然度、原片喊招是否切完整以及整体观看感受，等待手机审核。
