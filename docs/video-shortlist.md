# 下一批值得做的视频：四条主线、两条踩坑备选

原来的27条是开发事件素材，不等于27期视频。它们过于集中在美术返工，而且多条复用了同样的“技术通过、品质未完成”冲突。今后选题先看本页和 `research/pitches.json`，再回事件库找证据。

本轮只选6个。每集回答一个具体问题，要有能看懂的动作、反差或结果；不靠提交数、测试数、素材数量撑标题。顺序建议：核心机制 → 手感 → 风铃平原 → Harness/Skills。两条踩坑可以穿插，缺对照素材时先保留，不强行开拍。

## V001 · 枪是用来赶路的？我的游戏靠反冲跳跃

**已选为 ep003；用户追加六条武器分支，约4分钟。** 给看过初心介绍的观众一个继续关注的理由：这款游戏实际玩什么。

开头直接给下射弹起、空中改方向和落地，不先解释世界观。接一句：“这把枪，主要工作可能不是打怪。”

先用普通枪讲反冲，再逐一展示三连机关枪、散华手里剑、恒流激光、遥控回旋刃、磁吸遥爆雷和坍缩奇点的动作及限制。它们改变的是起跳、出手和落点的节奏。加入一次失败或未开枪对照，再说明次数/资源/恢复怎样限制无限飞行。肉鸽成长和能力锁只在结尾交代当前范围，不做整张技能树说明书。

**观众看点：换一种武器，就换一种赶路办法。** 不逐件报伤害，不把15个装备节点说成15套独立武器，也不把练习场装备等同于正式成长全部完成。

证据：[PR65](https://github.com/zhipijun1996/gunman-rush/pull/65) 的动作/位移合同、52.38秒全武器原片、38.37秒动作预算原片均已核对。现有练习片是旧手绘外观；若以当前像素版本介绍，要在独立副本补同版三武器演示，或者明确标注历史开发演示。

## V002 · 打中了，却像没打中：我给游戏补了哪些手感

**约2分半到3分半。** 讲一次命中如何被玩家感知。

从真实试玩反馈“主角没有受伤反馈……同理怪物也是”进入。围绕一次命中讲出手/弹道、受击姿态、闪光和声音、实际位移。重点是表现与真实命中同步，不是屏幕上堆更多粒子。

中途用一个真实坑作反转：加普通击退后，地面怪被推出平台却留在半空。或者用已有旧片展示“激光跟不上枪口”。二选一为主，另一条最多做短梗，别重新讲成错误清单。

**观众看点：同一次攻击为什么终于“看得懂、听得见”，以及增强反馈怎样反过来破坏控制。** 结尾展示修正版交战，但不替用户宣布“已经很爽”。

证据：[PR96](https://github.com/zhipijun1996/gunman-rush/pull/96) 的原始用户反馈、伤害表现/移动冲突报告及9.27秒双方交战原片；[PR65](https://github.com/zhipijun1996/gunman-rush/pull/65) 有3.85秒激光旧错片和后续修正说明。悬空故障目前有记录，未找到可直接用的原故障录像；需补旧版重录，或明确用记录和示意呈现。不同版本对照不能冒充同参数关闭特效的受控实验。

## V003 · 风铃平原：这一枪该打怪、开门，还是赶路？

**约2分半到3分半。** 用一段探索介绍第一地区，而不是朗读地区设定。

开头在真实场景里提出一次选择，随后展示结果。沿正式入口的一小段路线，选射击机关、移动齿轮/渡台、可选奖励或捷径三件事；让观众理解站位、落点和探索顺序如何相互影响。最后短展示Boss及当前仍需调整的密度/可读性。

**观众看点：同样的射击，在这个地区如何变成不同的决策。** V001展示武器移动方式，本集展示场景如何使用这些动作；不再重复整个武器介绍，也不重讲美术返工史。

证据：[PR94](https://github.com/zhipijun1996/gunman-rush/pull/94)、[PR96](https://github.com/zhipijun1996/gunman-rush/pull/96) 的正式两图、机关/捷径和Boss原片。需要补30–60秒从正式入口到分路/奖励的连续导览。历史八关、旧护甲开放窗口和后来的连续战斗分开，不能混成当前规则。

## V004 · AI交作业，我为什么还得给它配个验收器？

**约3–4分钟，建议已有两三期实机后再发。** 观众先认识游戏，再看开发方法。

开头展示一个具体事实：导出子进程退出0，同一份日志却有 `Parse Error: Busy`，严格Harness拒绝了这次交付。接着讲Skills怎样规定任务步骤与证据，Harness怎样真正执行检查、发现失败并留下记录。

再来一次反转：检查器自己的完成判定，也曾被代码审查指出漏洞。工具同样需要反例和审查。最后用游戏画面落地：可运行、正式接入、视觉和玩法体验要分别验证，工具没有自动审美通行证。

**观众看点：一次看似成功的交付怎样被查出问题，为什么“验收器也要验收”。** 不做命令行教程，不宣称加几个Skills就能让AI自动做出好游戏。

证据：[PR55](https://github.com/zhipijun1996/gunman-rush/pull/55)、[PR57](https://github.com/zhipijun1996/gunman-rush/pull/57) 的原始失败日志、报告和[完成判定审查意见](https://github.com/zhipijun1996/gunman-rush/pull/57#discussion_r4250691528)。本轮核对了原代码与历史审查，没有重跑或证明该审查问题已经修复。故障注入/模板演练须标注，不能当成自然发生的新事故。

## V005 · 钩索钩中了，为什么我还是追不上怪？

**踩坑备选，约1分半到2分半。** 开头：“钩中了。然后我和怪物开始赛跑。”

真实旧问题是：拉近后的抵达检查晚了一帧，逃离的目标先离开停止圈，于是持续追赶到超时。修正为本次实际移动之后结算抵达。讲清命中与抵达是两件事，展示左右两侧的旧错/修正对照，就足够撑起一条短片。

证据：[PR71](https://github.com/zhipijun1996/gunman-rush/pull/71)。旧实现反例原日志明确记录移动目标失败；专项修复与当时完整回归失败分别保留。**核心对比录像待补**，现有GUI片不能自动当成移动目标旧错片。历史版本现在重录必须标注。

## V006 · 我设计的双钩挑战，被一发反冲绕过去了

**踩坑备选，约2–3分钟，反差最强。** 先展示计划中的双钩，再展示普通跳跃接一次反冲、不用钩索也能到达同段目标。

森林v13早期双钩段，原始 `noH_oneR` 与 `noH_twoR` 记录都为 `target_reached`。这能引出一个明确问题：证明连招“能过”，不等于证明这段路线“值得用这个连招”。可以讨论保留有趣捷径，还是重新创造机制价值，不预设唯一答案是堵路加刺。

证据：[PR97](https://github.com/zhipijun1996/gunman-rush/pull/97)。已读压包内原始日志与归档说明，抽取并取帧检查了28.85秒森林旧源连续原片。**无钩反例自身的对比录像待补**。反例包含普通跳跃，只涉及一段，不是整个森林一枪通关；发现来自复查，不是假想的真人玩家反馈。深层三种替代策略没过，也不证明所有其他解法都不存在。
