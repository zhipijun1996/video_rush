# 拍拍波：创造三格气大招与B中招反应

用户已经认可波动拳段方向，本轮只改衔接台词、B中招反应和相应表演，不扩为新全片。

A原来试探地说“那……三格气呢？”，现在明确讲“直到我创造了，三格气的大招！”。用户的“到我创造了”按“直到我创造了”理解，已通过可选问题及进度说明告知，没有将未回答写为用户已确认。新配音4.0秒，先恢复小学生本音，再得意强调大招；三指手势在第二个分句出现。B不再问“我的反弹呢”，新录“还能这样？！”约1.34秒，并改为近景的手臂后缩、眼镜下滑、缩瞳、抬眉、张嘴和下巴下落。保留B的蓝色圆眼镜，避免人物身份混乱。随后A原有得意回应仍保留。

两句均用实际本地Qwen3-TTS 1.7B VoiceDesign重新表演，不用旧声音改字幕。母带、原始WAV、传输AAC及后端回执保留在build/。extra/CREATE-A.m4a与extra/SURPRISE-B.m4a提供单独试听，new-voice-receipts.json保存可追溯元数据。自动转写识别A为“直到我创造了三格器的大招”、B为“还能这样”；术语“气”有同音文字误识，不把自动转写冒称人工听审通过。

新台词实际时长驱动镜头、字幕与所有后续时间点平移，游戏源片段的in与seconds不动。本地已对比波动拳动作和实机的13段编码文件SHA256，逐项与V4相同；不是只比较编排文本。日语喊招、12/9/6/4/3帧加速与双重曝光方案沿用。背景音乐继续在真实命中后退出，让B的惊讶保持留白，最后的原主题短收尾跟随新末句时间点重算。

入口：`python -m tools.make_paipai_dialogue`，随后`python -m tools.paipai_dialogue_delivery`。同一入口用spec中的dialogue_changes替换已认可短片的指定台词，避免下次每改一句都重写剪辑器。Actions通过两个有序VOICE块恢复84635字节的实际表演包，固定SHA256写入episodes/ep008-v5-lines.json；旧桥接声只为重建前版时间基准，最终时间轴不播放它。原动漫、录音与游戏bank按既有SHA验证，许可未确认状态不变。

输出为独立build/episodes/ep008-v5-lines/，保留V4与旧全片，没有B站/Toy投稿；配音、颜艺和衔接仍待用户审核。
