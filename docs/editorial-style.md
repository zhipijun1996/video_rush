# 默认视频风格（用户2026-10-21修订）

以轻快、有个人感的B站游戏开发记录为主。少铺垫、少流程讲解，快速给观看理由。通常3–5分钟；简单自我介绍约2分钟，不用凑时长。背景、转折和实机结果交替，不连着朗读文档。

- 允许适度自嘲、反差和梗字。笑点来自愿望与现实、预期与真实结果；不编造具体失败、用户反馈、投入时长、学历职业、收入和家庭背景。
- 原创表情/梗图优先，短暂出现；屏幕字幕和实机仍是主角。不为每句都加音效，不遮挡角色、落点和机关。
- 尽量2–7秒一个信息点，以叙事需要为准。动作镜头保留看懂起跳—反冲—落地的连续性，不为了快切掩盖失败。
- 用有来源的实机说明当前能力；设计图示明确“设计目标”。开发Lab、历史原片和正式消费者分别标注。个人喜好来自用户自述。
- 可短引用官方发布的其他平台跳跃游戏画面，用于讨论个人喜好/灵感；核实来源、记录权利状态与署名，不抓取其他UP主的录像，不冒称是本作、不混用原作音乐、不臆造授权。
- 面向观众只显示必要的来源类别和版本边界。SHA、测试数量、技术细节放sources.json，不把介绍视频做成工程报告。
- 人声优先，默认带一点BGM。用户上传或指定曲目时优先用指定音轨，保留文件SHA和来源，不臆造作者或许可；没有指定时使用原创/许可清晰的轻配乐。加少量原创音效，自动压低配乐并做首尾淡入淡出。试听与审美仍待手机审核。

# 默认交付

用户已明确授权：以后成片直接放 **GitHub预发布（Prerelease）**。无需再次请求确认，不经过Actions/Artifact作为常规下载入口，不自动上传B站，不升级为正式Release。

先本地完整生产与技术验收，查看关键帧；提交/推送代码及分镜，最后`python -m video_rush deliver build/episodes/epNNN`。已提交干净工作树可直接`produce`，默认在生产后交付预发布。`--local-only`仅用于调试/本地核验。

每期预发布必须直接附`final.mp4`、`cover.png`、独立`bilibili.md`（推荐标题、备选标题和可复制简介）及完整资料ZIP；说明区同步展示投稿资料。缺少任一必要文件阻止发布。手机点击MP4即可下载。说明区标注技术验收状态、人类审核仍待确认、素材版权。禁止把技术PASS说成审美PASS。更新使用新修订tag，不能覆盖已有正式Release。

旧Actions工作流保存在docs/archive/produce-actions.yml，仅供历史复现；已移出活动工作流目录。

当前临时交付修订：用户在Release附件连续401后明确改为Actions下载。本期恢复GitHub托管Runner生产并上传Artifact（14天），指定曲目使用前145秒、单声道Opus 20kbps副本；主素材/配音/验收流程保持真实。手机无需提供新的Token。完成后给出实际Artifact链接；这是重新生产版本，不冒称复用原MP4字节。

九武器重制反馈：介绍武器先从真实关卡里的路线与连招展示区别，不把攻击标签和数值当全部特色。核对基础类型、二级分支和三级主动技能的统计口径；二段位移必须实录变向，不能仅凭单一方向例子给人“只能直着走”的印象。幽默优先来自操作用途的反差和短自嘲，配合真实连招节奏与原创贴图，不伪造受访者/试玩反馈或新增玩法。
