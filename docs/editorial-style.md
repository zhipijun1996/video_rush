# 默认视频风格（用户2026-10-22修订）

最新口播要求优先：像开发者正常向朋友介绍自己的游戏。先把动作、区别和想法讲清楚，不为每段安排笑点。用户认为ep003-r2的强行幽默和AI味明显；娱乐化不等于持续抖包袱。

ep01追加反馈（2026-10-22）：用“为啥我的游戏这么4399”自嘲早期画面，加强概念与实机的反差，多展示项目已有AI漂亮概念图。用短表情切入、概念快切和少量转场提速，别靠长小剧场拖节奏。用户提出的《动物井》式辨识度及更适合AI持续生产，是个人选择/下一步目标；不说本作已达到其美术水准或AI已能稳定量产。不将免费、CC0、作者自定义许可统一叫开源；概念、预览、实机和原创表情在每次快切后各自标注。

ep01再次补充：优先使用用户上传的五张概念/风格板，保留原字节与来源，不将图内HUD或“可实现”字样当真实验收。解释固定构图与变化布局的冲突时，限定为本作的随机地图目标，不断言肉鸽只能用TileSet或手绘无法随机化。TileSet的拼接、转角、风格、尺度和可读性本身也需要设计。三层视差用明确标注的原理动画加实际镜头移动的历史录像解释；动画不冒称新增实机或性能测量。

- 删除硬凑的拟人和跨领域比喻，例如“快递和收件人都是我”“脚说先飞了”“直升机资格证暂时不发”。不要把这些换成另一批生硬笑话。
- 可少量使用中国网络里自然的词，如真实连招后的“上头”，或看到新用法时的“还能这么玩？”。是否合适由上下文决定，不设梗数量指标，不追热点、不连续堆叠，不用“懂？”催观众认同。
- 口播以具体、简短的日常句子为主。读起来像说明书、营销稿或在表演段子时，重写成直接讲画面和个人想法。保留正常的连接句，不机械地每句都做反转。
- 贴图、标题、结尾互动和投稿简介也遵守同样标准。删掉包袱后可缩短视频，不用空话补时长；配音自然度和幽默是否成立仍需手机试听，自动检查不能替用户签收。

以轻快、有个人感的B站游戏开发记录为主。少铺垫、少流程讲解，快速给观看理由。通常3–5分钟；简单自我介绍约2分钟，不用凑时长。背景、转折和实机结果交替，不连着朗读文档。

- 允许适度自嘲、反差和梗字。笑点来自愿望与现实、预期与真实结果；不编造具体失败、用户反馈、投入时长、学历职业、收入和家庭背景。
- 原创表情/梗图优先，短暂出现；屏幕字幕和实机仍是主角。不为每句都加音效，不遮挡角色、落点和机关。
- 尽量2–7秒一个信息点，以叙事需要为准。动作镜头保留看懂起跳—反冲—落地的连续性，不为了快切掩盖失败。
- 用有来源的实机说明当前能力；设计图示明确“设计目标”。开发Lab、历史原片和正式消费者分别标注。个人喜好来自用户自述。
- 可短引用官方发布的其他平台跳跃游戏画面，用于讨论个人喜好/灵感；核实来源、记录权利状态与署名，不抓取其他UP主的录像，不冒称是本作、不混用原作音乐、不臆造授权。
- 面向观众只显示必要的来源类别和版本边界。SHA、测试数量、技术细节放sources.json，不把介绍视频做成工程报告。
- 人声优先，默认带一点BGM。用户上传或指定曲目时优先用指定音轨，保留文件SHA和来源，不臆造作者或许可；没有指定时使用原创/许可清晰的轻配乐。加少量原创音效，自动压低配乐并做首尾淡入淡出。试听与审美仍待手机审核。
