# 我想让AI生成的地图，真的值得探索

第一人称由用户自述与冻结规范整理，非私下构思时间线。体验目标不冒称已实现；同一份存档分两段接续展开，不是两张随机地图。

我想做的随机地图，是每次开局都有变化，到了岔路也真有得选：冒险抄近路，还是绕远找奖励？能通，只是起点。

以前我让AI反复试地图，后来发现，路线该有什么区别、挑战怎样衔接，这些设计判断得由我先说清楚。我开始自己抽象规则。

我把问题从小到大拆开：用格子统一布局，把内容做成模块，规定接口和内部路线，再组合探索地图。每一层，都得为玩家体验服务。

Block是统一布局格，默认一格一百二十八像素。Cell是里面的岩石、平台、怪物和机关。布局按格子算，具体形状不必长成格子。

把一段挑战装进矩形，就是Module模板。放到地图里一次，叫一个Instance。同一模板可以放多次，但不同实例的占用不能重叠。

Port是边界接口。位置、朝向、地貌、允许进还是出，都要明确。岩体、可穿平台和空中接口按规则匹配，两个模块才能准确对接。

Route再说明，从这个口进来，怎样到另一个口：需要跳跃、反冲还是钩索。方向和能力都要声明，左到右能走，反过来不一定。

同一模块，接左右可以穿越，接上方可以攀升。不用的口要封住，允许镜像的方向也要单独验证。这样才能复用内容，又守住动作边界。

这些实例组成Map：一份信息是摆在哪里，另一份是玩家真正能怎么走。所有实际通路都得算进去，不能默认同一模块里各个口全通。

然后才是我真正关心的：两条路，玩起来有什么不同？短路更险，长路更稳，奖励值不值得绕？多画几条线，不会自动产生探索欲。

我希望每局的路线和挑战组合都有变化。种子影响生成过程，玩家根据动作、风险和收益选路。随机性和探索选择，两样都要。

奖励支路可以原路折返，也能单向绕回，或者汇入另一条路。它决定探索后怎么继续，也影响玩家愿不愿意为额外挑战停一下。

我希望先用图变换，定下分叉、汇合和奖励关系，再让模块去实现。这层管玩家为什么想走，下面的搜索负责具体怎样拼出来。

这套设计里，AI辅助离线做内容，在线由程序搜索。内容可复用、算法可替换；缺转接就补模块，体验不好就回头改路线设计。

第一种，前沿生长。沿开放口找候选，用尺寸、接口和路线约束筛选，再兼顾重复和空间利用。从合法候选里随机选，继续向外长。

第二种，深度优先加回溯。先试一条，后面不满足约束，就退回来换。它共用这套模块规则，但要限制尝试预算；目前是指南备选。

原型闭环用的是Beam：每层保留几条有希望的候选，一起找。当前最多三层、每层十八个状态。它解决局部怎么接，不保证最好玩。

这些搜索，负责找到满足约束的组合。要往好玩靠，还得比较动作节奏、风险收益、路线差异和重复程度，最后拿真实试玩校准。

目前二十个固定种子，十六个通过静态检查，四个被拒绝。记录这些，是为了定位问题、稳定迭代，还不能证明地图已经好玩。

这段生长按现有存档的位置展开，模块正在往上下左右拼起来。它说明布局原型在推进，真实模块和物理认证还没有接上。

以前我总让AI再想个办法。现在，我先把想要的体验拆成能讨论、能验证的规则，再用算法去找。高考数学的感觉，是这么找回来的。

接下来，我想把它接到真实挑战里，让每次开局有变化、岔路有取舍，让人愿意多探索一步。这些都还在打磨，也欢迎大家给我建议。
