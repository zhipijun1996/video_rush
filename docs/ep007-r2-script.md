# AI地图总翻车，我决定先把“题目”写清楚

第一人称由用户自述和规范整理，是抽象思路的叙述，不编造私下构思时间线。算法演示不是实机或项目执行录像。

起点能到Boss，拿完奖励却走不出去。这样的地图，算生成成功吗？为了不再反复踩这种坑，我先给生成器重写了题目。

我之前一直让AI找办法、换算法、生成地图。但“好玩”三个字，省略了太多判断。我要的分叉、挑战和奖励关系，并不会自动长出来。

尤其这是个平台游戏。两块地方挨着，不代表跳得过去；能下去，也不代表能回来。只描述地图的形状，根本不够。

所以我开始把问题拆开。一小段挑战里，玩家能怎么走？两段挑战之间，怎样才算接上？整张地图，又要形成什么探索关系？

先把局部挑战装进矩形模块，用统一的格子记录大小和位置。生成器就能判断哪里放得下，也能直接排除重叠。模块内部的形状，仍然可以很自由。

接着，我给模块定义接口。它在哪，朝哪边，脚下有没有支撑，允许进还是出，都要说清楚。这样“能连”就不只是看着顺眼。

但接口对上，还没结束。我还要声明：从左边进来，能到哪个出口？靠反冲还是钩索？反方向能不能走，要另外验证。

于是算法终于能给我具体理由：这里重叠了，这个口方向不对，或者这条路需要玩家还没有的能力。失败不再只剩一句“不太行”。

整张地图就同时有两份信息：模块摆在哪里，以及玩家真正能怎么走。验证时还要把实际存在的捷径算进去，不能只看我原先规划的线。

同一个模块，还能有不同用法：接左右做穿越，接上方做攀升。不用的口要封好，允许的镜像方向也要单独验证。内容不必每次重画，但这些复用方式都得先验收。

第二个好处，是把内容和搜索办法分开。模块怎么描述、什么算有效，先保持一致。之后换算法，就能比较它们到底找得快不快、稳不稳。

第三个好处，是失败能反过来指导内容制作。比如总缺一种向上的转接，就去补这种模块。我终于能告诉AI具体缺什么，而不只是让它再多画一些。

那具体怎么生成？我用几个小动画讲。它们共用模块、接口和路线，区别在于：下一步先试谁，走不通怎么退，几条方案同时找。

第一种，是从一个开放接口往外接。程序先按接口类型和朝向查候选，再用位置、权限和占用规则筛一遍。不是随便挑一块塞进去。

合法候选里，再看能不能顺便连上其他口、占地会不会太散、模板是不是重复太多。原型从靠前的候选里随机选，既有约束，也保留变化。

接上一块，新接口又变成下一轮的起点。模块尺寸和口的位置不同，地图就能往上下左右发展。前沿生长比较适合这种向外扩展的任务。

但如果两端已经固定，要求中间补一段，把环接上，事情就变难了。随便长过去，可能位置差一格，或者出口方向不对。

一种办法叫深度优先搜索。先试一个模块，再往后试。后面发现接不上，就撤掉这一步，换另一个候选。之前那套规则，负责判断每一步是否合法。

这招直观，但分支多了，也可能试很久。所以要限定展开和回退预算。预算用完，得明确失败或走验证过的备用方案，不能输出一张其实没接上的图。

现在原型补局部闭环，用的是Beam Search。它不会只押一条路，而是每往前一层，都保留几条更有希望的候选，下一轮一起往前找。

比如更靠近目标、空间还放得下，就优先留下。原型最多往外试三层，每层保留十八个状态。它是在预算里找可行连接，不保证全局最优，也可能失败。

这就是模型的用处。前沿生长、回溯、Beam，找法不同，但都拿同一份接口和路线判断。以后比较算法，终于可以少混进一些“题目本身没说清”的问题。

不过，接得上不等于值得探索。我还希望先规划：这里分两条路，一条短但危险，一条长但稳，奖励拿完能绕回来。这叫探索骨架。

可以用图变换，逐步加分叉、回路和汇合。骨架提出“这里需要一段向上挑战”，具体选哪个模块、放在哪里，再交给空间搜索。两层不是同一个问题。

拼完，再把所有真正成立的路重新构图：主路通不通，奖励有没有去向。至于两条路是不是玩起来真有区别，还要看动作和风险，最后得试玩。

开头那种失败，问题就在这里。上口能到左口，左口能到下口，看着好像能接。可第一段已经是离开，第二段需要重新进入；外面的单向关系偏偏不允许。

目前连续测二十个种子，十六个通过静态检查，四个拒绝：一个奖励到不了，三个拿完没法继续。失败没有被删掉，下一步就知道要把回程检查提前。

这张原型图，已经能把不同尺寸的模块往二维空间展开。但它用的还是占位库，不是正式可玩地图。这个进展得承认，这个边界也得留下。

接下来还要接入真实模块，验证动作、接缝、封口和镜像，再补失败恢复、探索节奏。这套机制给了我推进的方法，还没有直接给我一个好玩的游戏。

我真正想留下的，是这条循环：把需求说清楚，让程序搜索，用证据验收，再根据失败补规则、补内容。这样每次尝试，才有机会积累下来。

没想到做游戏，又找回了高考做数学题的感觉。这回还得自己出题。下一步，把这些规则接到真实挑战上，看看是不是真能减少翻车。也欢迎大家帮我挑挑问题。
