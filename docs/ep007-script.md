# 为了让AI生成地图，我又开始做数学题了

第一人称经用户自述与冻结规范整理，AI配音。所有画面为解释图或原始工程图。

我做独立游戏，做到开始列集合、算坐标、画有向图了。高考做数学题的感觉，居然以这种方式回来了。

上期我还在反复让AI试地图。这次我自己制定了一套模型和规则。想要稳定的方法，得先把“好好生成”拆成能检查的问题。

先从最小的概念开始。布局格、内容、模块、放置实例、接口，还有模块里面的路线。名字有点多，但它们分别管不同的事。

第一层是布局格，默认一格一百二十八像素。模块放在哪里、占多大，都按整数格计算。这样拼地图时，大家用的是同一套坐标。

格子里具体放什么，是另一回事。岩石、平台、怪物、宝箱，都叫内容实体。它们保留自己的形状和碰撞，不用长成一格一格。

第二层是模块。一个矩形范围里，装着具体内容、接口、路线，还有玩法标签和认证资料。矩形是给生成器算占用的，游戏画面不用画个框。

同一个模板放三次，是三个实例，不是三个新模块。每个实例单独记录坐标、镜像方向，以及这次启用哪些接口。内容成本和放置数量得分开算。

最基本的一条：实例不能重叠。可以一高一低、上下发展，也可以共用边界，但不能让两个模块占同一块空间。先把这道几何题做对。

第三层是接口。它落在边界某个小格的外侧边中心，不要求在整个模块的正中间。同一侧能放多个口，模块就可以自然地错层拼接。

接口还分地貌：岩体、可穿平台、空中。同类才能接同类。比如岩体口只在左右边；底部不能设空中入口，不能指望人从下面凭空掉进来。

然后是方向。输入口允许进来，输出口允许出去，双向口两边都行。图上两块贴住了，只说明位置挨着，还得看方向能不能接。

一次连接要同时满足：接口世界坐标重合、朝向相反、地貌相同、权限兼容。正式内容还要验证真实接缝。少一条，都不能算接成功。

第四层，模块内部到底怎么走？从左口到右口，可能是一段反冲跳；从左口到上口，可能要用钩索。左到右能走，不代表右到左也能走。

每条路线还要写清能力要求、动作、难度、预计时间和进出条件。不是AI画根箭头，说“这里能过”，这条路就真的存在了。

比如这局只有跳跃和反冲，要求钩索的路线就过滤掉。需要的能力，必须包含在已有能力里。建图时先固定这份输入，不逐步模拟血量和能量。

一个模块不必把所有口都接出去。但不用的口必须封住，而且不能挡住这次要走的路。摆点荆棘、扣点血，人还能跳出去，这不算封好了。

还有个容易偷懒的地方：我没打算让玩家走这条路，不等于玩家走不了。所有实际能走的连接都得算进去，不能只验证自己画的理想路线。

镜像也不是把动作倒放。入口翻到右边，它仍然是入口。地形、碰撞、动作方向要一起翻，并且单独验证。镜像不凭空增加一个新模板。

最后才是整张地图。图里的节点，要细到某个实例的某个接口。跨模块走连接，模块内走真实路线。不能把一个模块缩成一个默认全通的大点。

奖励支路也得讲清去向。可以拿完原路返回，可以单向绕回来，也可以汇入另一条路线。不是把宝箱塞到边上，这道题就结束了。

机关门也只按初始方向算。以后开了可能双向，那是游戏运行时的事。不能为了让验证通过，先假设玩家已经把门打开。

规则齐了，再谈生成。指南里希望先定探索意图：哪里分叉、哪里汇合、两条路的动作有什么不同。这部分是目标，当前原型还没完整做出来。

运行时给程序种子、区域、能力、配置和模块库版本。AI可以在离线阶段帮忙做内容；在线拼图用纯程序，不一边生成一边等大模型临场发挥。

现在已经实现的原型，先把模板按接口朝向和地貌建索引。要接哪种口，就找兼容候选，避免每放一块都从头乱猜。

放置位置也不用逐像素试。已知旧接口的世界坐标，减去新接口的局部坐标，就能算出新模块的原点。再检查，它有没有和已有模块重叠。

然后沿开放接口向外长。原型会考虑多接通几个口、少撑大占地、少重复模板，再保留一点随机性。不是先画三条横线，再往上填内容。

闭环就更难了，两头位置已经固定。现在用有界搜索，试一小串中间模块，每层只留一部分候选。预算用完还没接上，也不能画条线冒充成功。

最后分两层验收。硬规则不过，就拒绝；过了，再比较路线差异、动作节奏、重复程度。评分只是辅助，不能靠分数证明游戏好玩。

目前存档里，这张样例有四十九个实例、六十一处连接和六处奖励。它验证的是布局和静态关系，里面还是占位模板。

可以看到，模块不再排成固定的几条横线。不同尺寸和接口偏移，让它往上下左右展开。不过，这些色块还不是可以直接玩的关卡。

连续二十个种子，第一次生成，十六个通过静态检查，四个拒绝，没有换掉失败种子。这四张都能从起点到Boss，但奖励出了问题。

一个奖励根本到不了，另外三个拿完奖励，没有合法的后续去向。所以只检查起点到终点，是不够的。

问题藏在模块内部：有上到左、左到下，不代表上能直接到下。到左口时已经是离开状态，得从外面合法绕回来，才能再从左口进入。

偏偏外部连接又有单向限制，绕不回来。以前一句“这个模块能连”，把关键细节省掉了。接下来要把奖励可达和回程检查，提前到放置阶段。

模块库也不能只追数量。缺哪种转向、哪种回程，就优先补哪种。现在测试用的是五十二个占位模板，真实编辑器内容还没正式接入。

所以还不能说已经稳定。真实动作、接缝、封口、镜像都要进Godot验证，失败恢复和玩法骨架也还要补。静态图过了，这事还没完。

但这次至少能说清楚，究竟是哪条约束出了问题。对我来说，这是在给后面的反复试验，搭一个能复现、能定位问题的基础。

本来想做游戏，最后又在查条件、找反例。高考数学的感觉是真回来了。下一步接上真实模块，再看看这些规则管不管用。有做过这类生成的朋友，也欢迎给我挑挑问题。
